# 竞品分析技能

## 描述
根据用户提供的竞品名称或链接，自动生成结构化的竞品分析报告，覆盖六大维度，输出可直接用于团队评审的分析文档。

## 使用场景
- 用户要求分析某个竞品或对标产品
- 用户需要市场调研或竞争格局梳理
- 用户提到"竞品""对标""对比分析""竞争"等关键词
- 产品评审前需要竞品背景材料

## 指令

### 第一步：信息收集
1. 根据用户提供的竞品名称，系统性地收集公开信息
2. 如用户提供链接，优先从链接提取关键信息
3. 如信息不足，向用户追问补充材料
4. **不编造数据**，信息不足时明确标注"待补充"

### 第二步：六维度分析框架

按以下六个维度逐一分析，每个维度不可省略：

#### 1. 产品定位
- 目标用户群体是谁
- 核心价值主张（一句话说清产品解决什么问题）
- 在市场中的位置（领导者/挑战者/跟随者/利基）
- 与本产品的定位差异

#### 2. 核心功能
- 主要功能清单（按重要性排序）
- 差异化功能（竞品有但我们没有的，或做得明显更好的）
- 功能完成度评估（成熟/可用/鸡肋）
- 交互体验亮点

#### 3. 用户画像
- 目标用户群体特征
- 典型使用场景（至少 3 个）
- 用户规模估算（如有公开数据）
- 用户口碑概览（正面/负面评价的主要方向）

#### 4. 竞争优势
- 相比同类产品的独特优势（至少 3 条）
- 技术壁垒或资源壁垒
- 生态或网络效应
- 品牌或渠道优势

#### 5. 主要劣势
- 明显短板（至少 3 条）
- 用户主要抱怨点
- 功能缺失或体验问题
- 潜在风险

#### 6. 机会点
- 未被满足的用户需求
- 可能的进攻方向（至少 2 个）
- 趋势红利（技术/政策/市场变化带来的机会）

### 第三步：输出格式
- 每个维度使用表格或要点列表
- 优势劣势需附简短依据，不空洞
- 机会点要具体可执行，附初步思路
- 总字数控制在 2000-3000 字
- 末尾附"一句话总结"和"行动建议"

### 第四步：质量检查
- [ ] 六个维度是否齐全
- [ ] 优势劣势是否有依据
- [ ] 是否有编造的数据（必须为零）
- [ ] 机会点是否具体可执行
- [ ] 是否与本公司产品做了关联分析

## 示例

**用户输入：** 分析 Notion

**输出（节选）：**

### 产品定位
| 维度 | 说明 |
|------|------|
| 目标用户 | 知识工作者、小团队、个人创作者 |
| 核心价值 | All-in-one 模块化工作空间，替代多个工具 |
| 市场位置 | 细分领域领导者，估值超百亿 |
| 与我们差异 | 我们偏前端开发协作，Notion 偏知识管理 |

### 核心功能
1. 文档编辑与实时协作（成熟）
2. 多维数据库（差异化，核心壁垒）
3. 模板市场（成熟，生态效应）
...

### 一句话总结
Notion 以模块化设计降低了工具切换成本，但复杂度对新手不友好，机会在于垂直场景的简化体验。
